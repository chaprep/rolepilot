# Project instructions

## Change logging

For every change made in this project, update the root `CHANGELOG.md` in the same task before finishing. This includes code, configuration, migrations, tests, documentation, and local deployment or saved-data operations.

Record the date, what changed and why, affected files, validation actually performed, deployment status where relevant, and known limitations. Distinguish implemented work from proposals or deferred features. Never record credentials, tokens, or other secrets. Preserve existing history; correct inaccurate entries explicitly rather than silently removing them.
